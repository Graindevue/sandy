# Coding Standards

Read and follow the repository contributor guide in @AGENTS.md and the domain
glossary in @CONTEXT.md. Stay precise about the vocabulary CONTEXT.md defines —
sloppy use leads to architectural drift.

## Style

- TypeScript 6, ESM (`"type": "module"`), Node 24. Prefer named exports.
- Formatting and linting are enforced by Biome — run `pnpm lint` (and
  `pnpm lint:fix` to auto-fix) before committing. Do not hand-format against it.
- Match the conventions of the surrounding file: naming, comment density, idiom.

## Testing

- Vitest. Run `pnpm test` (root) or the most relevant package's test command.
- Cover new/changed behaviour with tests; use descriptive test names.

## Architecture

- Keep packages focused on a single responsibility (see `packages/*`).
- Respect the decisions recorded in `docs/adr/`; do not silently contradict them.
- Convex code lives in `packages/convex-backend/convex/`; treat
  `convex/_generated/` as generated output (run codegen, never hand-edit).

## Commits & PRs

- Conventional Commits — subject starts with `feat:` or `fix:`.
- No AI co-author / "generated by" footers on commits or PRs.
- Branch from `staging`; open PRs against `staging`, never `main`.
